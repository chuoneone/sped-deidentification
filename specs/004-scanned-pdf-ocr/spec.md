# Feature Specification: 圖片型（掃描）PDF 的文字辨識與去識別化

**Feature Branch**: `004-scanned-pdf-ocr`

**Created**: 2026-10-15

**Status**: Draft

**Input**: User description: "支援「圖片類型的 PDF」（掃描檔、沒有文字層）：維持純前端，在瀏覽器內把頁面轉成圖片並辨識文字，再走既有的偵測、預覽、去識別化流程。偵測到這類檔案時要改用另一種載入畫面，顯示分析進度。只處理圖片裡的文字；還原的部分維持只還原文字。另外新增一份 5 頁、涵蓋不同版式的圖片型 PDF 範例供使用者體驗，範例區仍維持一排，UI 可視需要微調。"

延伸 `specs/001-doc-deidentify`（原本對無文字層 PDF 直接回報「無法處理」）與 `specs/003-ux-simplification`（範例區單排、狀態列格式限制提示）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 掃描檔也能去識別化 (Priority: P1)

使用者手上的申請書、收據、名冊是掃描或拍照後轉成的 PDF，裡面沒有可選取的文字。使用者照常上傳，系統在瀏覽器內辨識每一頁的文字，接著跟一般 PDF 一樣自動偵測姓名、身分證、電話等，讓使用者在預覽中核對、取消、手動新增，最後下載。

**Why this priority**: 掃描檔是目前唯一「整份無法處理」的常見文件類型，也是個資最集中的文件（申請表、收據、名冊）。

**Independent Test**: 上傳一份只有頁面影像的 PDF，確認預覽逐頁顯示辨識出的文字並標記出敏感資訊，可取消與手動新增，下載後得到去識別化 PDF 與編碼表。

**Acceptance Scenarios**:

1. **Given** 一份每頁都只有影像、沒有文字層的 PDF，**When** 上傳，**Then** 系統自動改用文字辨識處理，完成後出現與一般 PDF 相同的逐頁預覽與偵測結果。
2. **Given** 一份有文字層的 PDF，**When** 上傳，**Then** 行為與現在完全相同，不進行文字辨識、不顯示辨識畫面。
3. **Given** 辨識完成的掃描檔，**When** 檢視預覽，**Then** 文字出現在原頁面相對應的位置；表格與多欄的內容維持各自的欄位位置，不會擠成同一段。
4. **Given** 掃描檔中的中文姓名、地址，**When** 辨識完成，**Then** 中文字之間沒有多餘空白，偵測結果與同內容的文字型文件一致。
5. **Given** 辨識完成的掃描檔，**When** 檢視狀態列，**Then** 可看到此檔是「文字辨識」來源，並可在格式限制提示中讀到：辨識可能有誤需逐頁核對、輸出只含辨識出的文字而不含原頁面影像。
6. **Given** 一次選擇多個檔案，其中一個是掃描檔，**When** 上傳，**Then** 只有掃描檔需要辨識，其他檔案照常載入，最後全部出現在檔案清單中。

---

### User Story 2 - 辨識時看得到進度、可以取消 (Priority: P1)

文字辨識比一般讀檔慢很多（每頁數秒）。系統偵測到掃描檔時改用專屬的「分析中」畫面：顯示正在辨識第幾頁、整體進度、目前頁面的縮圖，並說明首次使用需下載辨識模型、文件不會上傳。使用者等不及或選錯檔時可以取消。

**Why this priority**: 沒有進度的長時間鎖定畫面會讓人以為當機；這是使用者明確要求的不同載入畫面。

**Independent Test**: 上傳 5 頁掃描檔，確認出現與一般讀檔不同的辨識畫面，頁數與進度條隨辨識前進；中途按取消，畫面立即恢復可操作且該檔未加入。

**Acceptance Scenarios**:

1. **Given** 上傳掃描檔，**When** 系統判定需要辨識，**Then** 顯示辨識畫面，包含標題（正在辨識圖片文字）、檔名、「第 N / 總頁數 頁」、整體進度百分比與進度條、目前階段（準備辨識引擎／辨識中）、目前頁面縮圖。
2. **Given** 第一次在此瀏覽器使用辨識，**When** 顯示辨識畫面，**Then** 說明需先下載辨識模型（標示約略大小），且文件內容只在本機處理、不會上傳。
3. **Given** 辨識進行中，**When** 按「取消」，**Then** 辨識立即停止，畫面恢復可操作，該檔不加入，並提示已取消；多檔時其餘檔案繼續載入。
4. **Given** 上傳的是一般檔案（Word、Excel、文字型 PDF 等），**When** 讀檔，**Then** 仍使用原本的簡易載入畫面。

---

### User Story 3 - 下載與還原只處理文字 (Priority: P2)

掃描檔去識別化後的輸出，與文字型 PDF 一樣是「把文字依原位置重新繪製」的 PDF：只含辨識出的文字（敏感值換成標記），不含原本的頁面影像。使用者之後把輸出檔與編碼表交給還原頁，即可還原文字內容；原頁面影像不在還原範圍內。

**Why this priority**: 確保掃描檔也遵守「輸出不殘留敏感資訊」與「可由編碼表還原」兩個原則；使用者已確認還原只需還原文字。

**Independent Test**: 對掃描範例做去識別化並下載，確認輸出 PDF 無任何影像且有文字層；再到還原頁上傳輸出與編碼表，還原後的文字與辨識結果完全一致。

**Acceptance Scenarios**:

1. **Given** 掃描檔已辨識並去識別化，**When** 下載，**Then** 輸出 PDF 每頁只有文字，沒有原頁面影像，敏感值皆以標記取代。
2. **Given** 辨識出的文字在輸出中依原位置重繪，**When** 開啟輸出檔，**Then** 同一行相鄰的文字段不互相重疊。
3. **Given** 上一步的輸出與編碼表，**When** 在還原頁上傳，**Then** 所有標記還原為辨識出的原文字。
4. **Given** 在還原頁上傳一份圖片型 PDF，**When** 讀檔，**Then** 不進行文字辨識，並顯示訊息說明還原需要本工具輸出的去識別化檔案。

---

### User Story 4 - 用掃描範例體驗 (Priority: P2)

沒有掃描檔的使用者，可以在上傳頁的範例區直接載入一份 5 頁的掃描範例，體驗辨識與去識別化。範例要足夠擬真，涵蓋中文、英文、表格、數字等情境：每頁是不同版式與字體（中文信函、手寫填寫的申請表單、多欄名冊表格、英文商業發票、中英雙語名片），並帶有掃描檔常見的灰階、輕微傾斜與紙張底色。範例區仍維持一排。

**Why this priority**: 文字辨識是新能力，使用者需要一份不含真實個資、版式多樣的檔案來確認效果。

**Independent Test**: 在上傳頁點範例區的掃描範例「載入」，看到辨識畫面並完成 5 頁辨識，各頁偵測到敏感資訊；在桌機寬度下範例區 5 張卡片排成一排。

**Acceptance Scenarios**:

1. **Given** 上傳頁，**When** 檢視範例區，**Then** 有 5 張範例卡片（Word、PDF、掃描 PDF、Excel、Markdown），桌機寬度下排成一排，掃描範例標示為圖片型、需辨識。
2. **Given** 掃描範例，**When** 檢視其 5 頁，**Then** 各頁版式不同：
   - 第 1 頁 中文信函：信頭、段落文字，內文夾帶契約編號、日期、金額、帳號等數字；
   - 第 2 頁 申請表單：格線欄位框、勾選框，欄位值以手寫風格字體填寫；
   - 第 3 頁 名冊表格：10 列以上、多欄（姓名、身分證字號、手機、Email、部門等）；
   - 第 4 頁 英文商業發票（Invoice）：英文段落與欄位、品項／數量／單價／金額表格、總計，並含台灣公司中文名、統一編號、電話與 Email；
   - 第 5 頁 中英雙語名片：同頁多張、彩色，中英文姓名、職稱、電話、Email、地址混排。
   每頁至少含 3 種類別的虛構敏感資訊。
3. **Given** 手機寬度（375px），**When** 檢視範例區，**Then** 不產生頁面水平捲動，卡片內容不被截斷。
4. **Given** README 的範例下載表與 `examples/` 目錄，**When** 檢視，**Then** 同樣提供這份掃描範例。

### Edge Cases

- **部分頁面有文字層的混合型 PDF**：只要任一頁有可擷取的文字，就視為文字型 PDF，沿用現有處理（無文字的頁面不辨識）；本功能只處理整份都沒有文字的 PDF。
- **整份辨識後仍沒有任何文字**（空白頁、純照片）：顯示「未辨識到任何文字」的錯誤，不加入檔案清單。
- **傾斜、模糊、低解析度或手寫**：辨識率會下降；辨識錯誤的值可能不會被自動偵測（例如身分證檢查碼因誤認字元而不符），需由使用者在預覽核對並手動圈選。未被辨識出的文字不會出現在輸出中。
- **頁數很多的掃描檔**：不設頁數上限（仍受單檔 20 MB 限制），以頁數與進度呈現，使用者可隨時取消。
- **辨識模型下載失敗**（離線、網路中斷）：顯示錯誤並說明可稍後重試；該檔不加入。
- **頁面中的照片、印章、簽名、表格框線**：不屬於文字，不處理，也不會出現在輸出中；框線不得被當成文字字元（例如「|」「_」）混入辨識結果。
- **原文中已存在形如 [類別:編碼] 的文字**：沿用現有提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 當 PDF 的所有頁面都沒有可擷取的文字時，系統 MUST 判定為圖片型 PDF 並對每一頁進行文字辨識；只要任一頁有文字，MUST 沿用現有文字型處理且不進行辨識。
- **FR-002**: 文字辨識 MUST 完全在使用者瀏覽器內完成；辨識所需的程式與模型 MUST 與網站一同部署、由同一個網站提供，整個處理過程不得對任何第三方網域發出請求，文件內容不得離開瀏覽器。
- **FR-003**: 辨識語言 MUST 涵蓋繁體中文與英文字母、數字及常見符號（`@`、`-`、`.` 等）。
- **FR-004**: 辨識結果 MUST 保留每段文字在頁面上的位置與大小，預覽 MUST 依原頁面位置逐頁排版；同一行中相距明顯的文字（表格欄位、表單欄位、並排名片）MUST 拆成獨立的文字段。
- **FR-005**: 相鄰中文字（含全形標點）之間 MUST 不出現辨識所產生的空白；英文與數字之間的正常空白 MUST 保留。
- **FR-006**: 表格框線、底線等非文字圖形 MUST 不得以「|」「_」等字元混入辨識結果。
- **FR-007**: 辨識完成後的文件 MUST 支援既有全部流程：自動偵測、預覽、取消、手動圈選新增、輸出方式、類別開關、重新偵測、批次與共用編碼、打包下載。
- **FR-008**: 判定需要辨識時，MUST 顯示專屬的辨識畫面（不同於一般讀檔畫面），內容包含：標題、檔名、目前頁數／總頁數、整體進度（百分比與進度條）、目前階段文字、目前頁面縮圖、取消按鈕，以及「首次需下載約 N MB 辨識模型；文件只在本機處理、不會上傳」的說明。辨識期間其餘畫面 MUST 不可操作。
- **FR-009**: 按下取消 MUST 停止辨識、釋放辨識所用資源並關閉辨識畫面；該檔 MUST 不加入檔案清單；多檔上傳時其餘檔案 MUST 繼續載入。
- **FR-010**: 非圖片型的檔案 MUST 維持原本的讀檔畫面與速度（不得因本功能而預先下載辨識模型）。
- **FR-011**: 辨識來源的文件 MUST 在工具列標示為文字辨識（例如格式徽章旁加註），格式限制提示 MUST 說明：辨識可能有誤需逐頁核對；輸出只含辨識出的文字，不含原頁面影像；未辨識出的文字不會出現在輸出中。
- **FR-012**: 辨識來源文件的輸出 MUST 是依辨識位置重繪文字的 PDF，不包含任何原始頁面影像；文字 MUST 縮放以容納於原位置的寬度內，避免相鄰文字段重疊。
- **FR-013**: 上述輸出與其編碼表 MUST 可在還原頁還原；還原結果的文字 MUST 與辨識結果一致。還原不處理影像。
- **FR-014**: 還原頁收到圖片型 PDF 時 MUST 不進行辨識，並顯示「此 PDF 沒有文字層；還原請使用本工具輸出的去識別化檔案」之類的明確訊息。
- **FR-015**: 整份文件辨識後沒有任何文字時，MUST 顯示錯誤且不加入檔案清單；辨識模型載入失敗時 MUST 顯示錯誤並可重試。
- **FR-016**: 系統 MUST 提供一份 5 頁、全為頁面影像的掃描範例 PDF（虛構資料），版式依序為中文信函、手寫申請表單、名冊表格、英文商業發票、中英雙語名片，整體涵蓋中文、英文、表格、數字（日期、金額、帳號、數量）情境，並模擬掃描（灰階或彩色、輕微傾斜、紙張底色）；每頁至少含 3 種類別的敏感資訊。英文拼音姓名（例如 Wang Xiao-Ming）不在內建規則範圍，作為示範手動新增的情境。
- **FR-017**: 上傳頁範例區 MUST 在桌機寬度以單排呈現 5 張範例卡片；掃描範例卡片 MUST 標示為圖片型、需辨識；375px 寬度下 MUST 無頁面水平捲動。
- **FR-018**: 網站上的支援格式說明、README（含範例下載表）、`examples/` 目錄與 `llms.txt` MUST 更新為支援掃描型 PDF；原本「掃描型無文字層」的邊界範例 MUST 改為反映新行為。

### Key Entities

- **辨識來源文件（OCR Document）**：由文字辨識產生內容的 PDF 文件；與文字型 PDF 共用相同的逐頁版面資料（每段文字的頁碼、位置、大小），另標記其來源為辨識，供狀態列與輸出使用。
- **辨識進度（OCR Progress）**：檔名、目前頁、總頁數、階段（準備引擎／辨識中）、整體進度、目前頁縮圖；只存在於辨識期間的畫面上。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 5 頁掃描範例在一般筆電上（辨識模型已下載後）60 秒內完成辨識；首次使用另需下載的辨識程式與模型合計不超過 10 MB。
- **SC-002**: 掃描範例中植入、且屬內建規則範圍的敏感值，自動偵測的命中率達 90% 以上；未命中者（含英文拼音姓名）皆可透過手動圈選補上。
- **SC-003**: 從上傳掃描檔到完成下載的整個過程，對第三方網域的網路請求數為 0。
- **SC-004**: 掃描檔的去識別化輸出加上編碼表還原後，文字內容與辨識結果 100% 一致；輸出檔中原頁面影像數為 0。
- **SC-005**: 按下取消後 2 秒內畫面恢復可操作。
- **SC-006**: 既有自動化測試全部通過；文字型 PDF 與其他格式的處理結果、讀檔畫面不變。

## Assumptions

- 「圖片型 PDF」以整份文件判定（所有頁面都沒有文字層）；混合型 PDF 不在本次範圍。
- 只處理影像中的文字；照片、印章、簽名等非文字內容不做遮蔽，而是因輸出只重繪文字而自然不出現在輸出中。
- 輸出不保留原頁面影像，與現有文字型 PDF 的「文字版面重建」一致；使用者已確認還原只需還原文字。
- 辨識模型首次使用時從本站下載，之後依瀏覽器一般快取重複使用；不寫入瀏覽器的儲存空間（遵守 constitution：瀏覽器儲存只放 pattern 設定）。
- 掃描範例由程式產生（虛構資料、模擬掃描的頁面影像），與其他範例同一套產生流程。
- 辨識正確率受原稿品質影響；本功能以「預覽核對＋手動新增」作為人工把關，不承諾手寫或嚴重傾斜文件的辨識率。

## 修訂 2026-10-16：100 MB 上限、手寫情境、保留不含文字的圖片

使用者在實作過程中追加三項需求：上傳上限提高到 100 MB 且超過時以警告擋住；範例要涵蓋手寫情境；範例要有「不含文字的圖片」，並在去識別化輸出中保留原始圖片（圖片可用 Codex 生成）。

- **FR-019**: 單檔上限 MUST 為 100 MB（去識別化頁與還原頁皆同）。選取的檔案超過上限時，MUST 以阻擋式警告視窗列出超限檔名與大小，使用者按「我知道了」後才關閉；超限檔不載入，同批其他檔案照常處理。
- **FR-020**: 掃描範例 MUST 涵蓋手寫情境：表單欄位以手寫填寫、英文手寫簽名，以及信函上含姓名與電話的手寫批註。
- **FR-021**: 掃描範例 MUST 含至少 3 張不含任何文字的圖片（照片、標誌圖形），以 Codex 生成，原始圖檔保存在版本庫中，供重新產生範例使用。圖片不得含人臉等可識別個人的內容。
- **FR-022**: 掃描檔中「不含文字的圖片區塊」MUST 從原頁面影像裁切，並以原位置與尺寸保留在去識別化輸出中。判定條件：該區塊在頁面上屬於圖像區域，且區塊內辨識不到任何文字。含文字的區域一律不保留影像。
- **FR-023**: 預覽 MUST 在原位置顯示保留的圖片並標示「保留圖片」；使用者 MUST 可逐張取消保留（例如照片可辨識出人物或證件），取消後輸出不含該圖，且視為文件內容變更（需重新下載）。
- **FR-024**: 還原維持只還原文字：還原後的檔案為文字版面重建，不含保留的圖片。

**Success Criteria 補充**：

- **SC-007**: 範例中的 3 張圖片在去識別化輸出中都以原位置保留；輸出中除了保留的圖片外沒有其他影像，使用者取消保留後該圖不出現在輸出。
- **SC-008**: 選擇 101 MB 的檔案時，100% 出現阻擋式警告且該檔未被載入。

**Assumptions 補充**：文字型 PDF 的內嵌圖片仍不保留（維持現行文字版面重建），本次只處理掃描檔；判斷圖片是否含文字依賴辨識結果，因此預覽提供逐張取消，作為人工把關。

## 修訂 2026-10-16（二）：以演算法提升辨識成功率

使用者希望透過演算法優化圖片轉文字的成功率。

- **FR-025**: 系統 MUST 在辨識前後加入不需額外下載的處理步驟以提高成功率，並以範例在真實瀏覽器流程量測前後差異，只保留確實有效的步驟：辨識前移除表格框線、加深彩色字；辨識後對證號／電話／統編做字形校正（須通過檢核碼或格式驗證才採用）、低信心字詞以純中文模型放大重讀。
