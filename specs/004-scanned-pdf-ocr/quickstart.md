# Quickstart: 驗證圖片型 PDF 辨識

## 準備

```bash
npm install
npm run examples   # 需要本機 Chrome（CHROME_PATH 可覆寫）；產生 public/samples/scanned.pdf 與 examples/01-核心流程/掃描文件.pdf
npm test
npm run build && npm run preview   # http://localhost:4173/
```

## 情境

1. **範例區單排**：開啟首頁，桌機寬度（1280px）下範例區有 5 張卡片排成一排，其中一張為「掃描 PDF」。
2. **辨識畫面**：
   - 在掃描範例按「載入」，出現辨識畫面，依序顯示「準備辨識引擎」與「第 1–5 / 5 頁」；縮圖隨頁更新。
   - 5 頁在 60 秒內完成。
3. **偵測與預覽**：
   - 預覽逐頁呈現文字，表格與名片各欄位分開排列。
   - 工具列顯示「文字辨識」標籤，ⓘ 格式限制中有 OCR 說明。
   - 自動偵測的命中率依 [contracts](contracts/) 與範例產生腳本列出的植入值計算，需達 90% 以上。
4. **零第三方請求**：在 DevTools 的 Network 面板中，所有請求都與網站同源（`ocr/worker.min.js`、`ocr/core/*`、`ocr/lang/*`）。
5. **取消**：重新載入掃描範例，在第 2 頁時按「取消辨識」，2 秒內畫面恢復可操作、檔案清單沒有新增，並出現「已取消辨識」提示。
6. **下載與還原**：
   - 按「下載（文件＋編碼表）」，輸出 PDF 只有文字、沒有影像。
   - 到「還原」頁上傳輸出與編碼表，所有標記皆還原。
7. **還原頁拒絕影像檔**：在還原頁直接上傳 `scanned.pdf`，顯示「沒有文字層；還原請使用本工具輸出的去識別化檔案」。
8. **一般檔案不受影響**：載入 Word 範例時仍是原本的「讀取檔案中…」畫面，Network 面板中沒有 `ocr/` 的請求。
9. **RWD**：375px 寬度下，範例區與辨識畫面都沒有水平捲動。
10. **保留圖片**：載入掃描範例後，第 1 頁的標誌與機房照片、第 4 頁的標誌與 SSD 照片以綠色虛線框標示「✓ 保留」；印章與手寫批註不會被保留。取消其中一張後下載，輸出 PDF 只含 3 張圖片。
11. **100 MB 上限**：同時選擇 101 MB 與一個小檔案，出現「檔案超過 100 MB 上限」警告視窗，按「我知道了」後只有小檔載入。
12. **辨識率量測**：`npm run build && npm run preview` 後執行 `npm run eval:ocr`（加 `-- --verbose` 看每頁漏抓、誤判、少讀與多出的字），以 `tests/fixtures/scanned-sample.answer.json` 為答案（方法與基準見 research R14）。
