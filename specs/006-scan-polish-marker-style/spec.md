## User Scenarios & Testing *(mandatory)*

### User Story 1 - 只要去識別化、不需要還原 (Priority: P1)

有些使用者只是要把文件交給外部（例如給 AI 摘要、給廠商參考、公開範例），日後不會還原，也不想保管編碼表。他們希望輸出裡只看到「[姓名]」這類類別標記，或像公文一樣以「○○○」佔位，而不是一串看不懂的編碼。

**Why this priority**: 這是實際使用者的需求；目前每次下載都會附帶編碼表、輸出也帶著編碼，對不需還原的人是多餘的負擔與疑惑。

**Independent Test**: 載入任一範例，在輸出設定選「類別」或「空白佔位」，預覽與下載的文件都只出現對應的標記、不含編碼，下載時沒有編碼表。

**Acceptance Scenarios**:

1. **Given** 已載入文件，**When** 在輸出設定的「標記方式」選「類別」，**Then** 預覽與下載文件中的每個去識別化項目都顯示為「[類別名稱]」（例如 [姓名]），不含任何編碼。
2. **Given** 已載入文件，**When** 選「空白佔位」，**Then** 每個被隱藏的字元都以「○」取代、字數相同，分隔符號（-、@、.、空白、括號等）原樣保留，例如「0912-345-678」→「○○○○-○○○-○○○」。
3. **Given** 標記方式為「類別」或「空白佔位」，**When** 檢視下載按鈕與更多選單，**Then** 按鈕改為「下載去識別化文件」，編碼表、合併編碼表、匯入既有編碼表、編碼範圍等與還原有關的選項都不顯示，狀態列註明「此標記方式無法還原」。
4. **Given** 輸出方式為「部分保留」，**When** 標記方式選「空白佔位」，**Then** 保留的字元照常顯示、只有隱藏部分變成「○」，例如「王小明」→「王○○」；選「類別」則為「王[姓名]」。
5. **Given** 已選不需還原的標記方式，**When** 改回「編碼」，**Then** 輸出回到可還原的編碼、下載再度附編碼表，原本的編碼範圍與匯入設定都還在。
6. **Given** 多個檔案、標記方式為不需還原，**When** 打包下載，**Then** 壓縮檔只含去識別化文件，不含任何編碼表。

### User Story 2 - 信函上的標題、條列編號、署名與手寫批註被讀出來 (Priority: P1)

掃描範例第 1 頁信函有幾處目前讀不出來：字距很寬的標題「通　知　函」、每段開頭的中文條列編號「一、」～「六、」、署名「董事長」，以及斜寫的手寫批註「10/8 已致電，改寄助理 丁承」。使用者希望這些內容都出現在預覽與輸出中，批註中的人名也能被偵測遮蔽。

**Why this priority**: 標題與條列編號是文件結構的一部分，遺漏會讓輸出看起來殘缺；手寫批註中的人名是個資，讀不出來就無法遮蔽。

**Independent Test**: 以評分工具辨識掃描範例，第 1 頁的這些內容都出現在辨識文字中，手寫人名被偵測。

**Acceptance Scenarios**:

1. **Given** 字距很寬的大標題（字與字之間有一個字以上的空隙），**When** 辨識，**Then** 讀出完整標題，字距在輸出中大致保留。
2. **Given** 段落開頭的「一、」「二、」…「六、」，**When** 辨識，**Then** 每個條列編號都出現在該段文字之前。
3. **Given** 稍微傾斜（約 3°）的手寫批註，**When** 辨識，**Then** 讀出「改寄助理 丁承」與手機號碼，人名與手機都能被偵測。
4. **Given** 字距加寬的署名「董事長　廖宜婷」，**When** 辨識，**Then** 「董事長」與姓名都出現。

### User Story 3 - 名片頁的文字不再互相重疊 (Priority: P2)

掃描範例最後一頁是六張略為傾斜的名片。目前輸出與預覽中，同一張名片上的相鄰幾行（例如地址與統一編號、電話與 Email）會稍微疊在一起，讀起來吃力。使用者希望每行文字都落在自己的位置，不互相覆蓋。

**Why this priority**: 名片、收據這類小字密集的版面很常見；重疊雖不影響去識別化本身，但影響閱讀與人工覆核。

**Independent Test**: 辨識掃描範例後檢查名片頁的預覽與輸出，任兩段文字的範圍都不重疊。

**Acceptance Scenarios**:

1. **Given** 一張名片上行距很密的多行文字，**When** 輸出與預覽，**Then** 每行文字以不超過原本行高的大小呈現，上下兩行不互相覆蓋。
2. **Given** 略為傾斜的名片，**When** 輸出，**Then** 同一行的字維持在同一行，不因傾斜被拆到上下兩行而與鄰行重疊。

### Edge Cases

- **不需還原的輸出被拿去還原**：還原頁找不到任何編碼時，提示「此檔可能是以『類別』或『空白佔位』輸出，無法還原」。
- **空白佔位的長度**：「○」等長會透露原本的字數（例如姓名是兩字或三字）；需要更高匿名性時應改用「類別」。介面說明此差異。
- **全部隱藏＋空白佔位**：整個值都變成「○」（分隔符號保留）。
- **自訂保留方式**：各類別依自訂的保留方式保留字元，其餘照所選標記方式呈現。
- **手動圈選新增的項目**：與自動偵測的項目一樣套用標記方式。
- **已下載後切換標記方式**：視為輸出內容改變，與目前切換輸出方式的行為一致（下載狀態重置、離開頁面前提醒）。
- **字距加寬但其實是表格欄位**（同一行的兩個欄位相隔很遠）：仍分成兩段，不併成一個詞。
- **還原頁、文字型 PDF、Word、Excel 的去識別化流程**：除了新增的標記方式外，行為不變。

## Requirements *(mandatory)*

### Functional Requirements

**標記方式**

- **FR-001**: 輸出設定 MUST 新增「標記方式」，三選一：編碼（[類別:編碼]，可還原，預設）、類別（[類別]，不需還原）、空白佔位（以「○」取代隱藏的每個字元，不需還原）。
- **FR-002**: 標記方式 MUST 與既有的輸出方式（部分保留、全部隱藏、自訂）獨立並用：輸出方式決定保留哪些字元，標記方式決定隱藏部分如何呈現。
- **FR-003**: 空白佔位 MUST 只取代隱藏部分中的文字與數字字元，分隔符號（連字號、空白、@、句點、括號、斜線等）原樣保留，「○」的數量等於被取代的字元數。
- **FR-004**: 預覽 MUST 與下載的文件一致：不需還原時預覽直接顯示 [類別] 或 ○；滑鼠停留仍可看到原文。
- **FR-005**: 選擇不需還原的標記方式時，下載按鈕 MUST 改為只下載去識別化文件；編碼表下載、合併編碼表、匯入既有編碼表與編碼範圍設定 MUST 隱藏；狀態列與輸出設定摘要 MUST 註明「無法還原」。
- **FR-006**: 不需還原的輸出 MUST 不含任何編碼，且不產生編碼表；多檔打包下載 MUST 只含去識別化文件。
- **FR-007**: 改回「編碼」時，編碼範圍（整批共用、沿用匯入的編碼表）MUST 恢復為切換前的設定。
- **FR-008**: 標記方式 MUST 適用於所有支援格式（TXT、Markdown、Word、Excel、文字型 PDF、掃描 PDF）與複製文字功能。
- **FR-009**: 還原頁在上傳的文件中找不到任何編碼時，MUST 提示可能是以不需還原的標記方式輸出。

**掃描辨識**

- **FR-010**: 系統 MUST 讀出字距寬於一個字的大標題（例如「通　知　函」），並在輸出中保留其字距。
- **FR-011**: 系統 MUST 讀出段落開頭的中文條列編號（「一、」～「十、」），且編號位於該段文字之前。
- **FR-012**: 系統 MUST 讀出約 3° 傾斜的手寫批註，使其中的姓名與電話可被偵測。
- **FR-013**: 系統 MUST 讀出字距加寬的署名（例如「董事長」）。
- **FR-014**: 掃描 PDF 的輸出與預覽中，同一頁的任兩段文字 MUST 不互相重疊；文字大小不得超過該行原本的行高。

**文件**

- **FR-015**: README MUST 說明標記方式的三個選項、何時選哪一個，以及不需還原時的下載與限制；README 與網站的截圖 MUST 更新為最新介面。

### Key Entities

- **標記方式（Marker style）**：編碼／類別／空白佔位；整批文件共用一個設定；決定隱藏部分的呈現方式，以及是否產生編碼表。
- **輸出方式（Output mode，既有）**：部分保留／全部隱藏／自訂；決定每個值保留哪些字元。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三種標記方式在所有支援格式下都能下載；「類別」與「空白佔位」的輸出中找不到任何編碼，下載不含編碼表；「編碼」的去識別化 → 還原循環維持與原文一致。
- **SC-002**: 空白佔位的「○」數量與隱藏的文字數字字元數 100% 相同，分隔符號 100% 保留。
- **SC-003**: 使用者從展開輸出設定到下載不可還原的文件，最多 3 個步驟（選標記方式 → 下載）。
- **SC-004**: 掃描範例第 1 頁：標題「通知函」、條列編號「一」～「六」、「董事長」、手寫「改寄助理 丁承」全部讀出；第 1 頁手寫值 2/2；第 1 頁字元召回由 96.7% 提升到 98.5% 以上。
- **SC-005**: 掃描範例名片頁的輸出中，任兩段文字的範圍重疊為 0；名片頁字元召回不低於現況（98.5%）。
- **SC-006**: 掃描範例整體不退步：字元召回 ≥ 98.8%、印刷值 ≥ 138/144、線段 66/66、底色 18/18、勾選框 10/10；角度樣本各頁字元召回不低於現況 1 個百分點以上；5 頁總辨識時間增加不超過 15%。
- **SC-007**: 既有自動化測試全部通過。

## Assumptions

- 預設標記方式是「編碼」，與現行行為相同；不需還原是使用者主動選擇。這是對專案「可還原」原則的刻意例外，會在專案憲章中記錄（使用者明確選擇、介面清楚告知時才允許）。
- 標記方式與輸出方式一樣不寫入瀏覽器儲存空間（憲章只允許儲存規則設定），每次開啟網站都從「編碼」開始。
- 「○」取代的是被隱藏部分的文字與數字；中英文字元都以一個「○」取代一個字元。
- 名片重疊的判定以每段文字在頁面上的範圍為準；為了不重疊而縮小字級是可接受的。
- 第 1 頁的印章文字（「泰宇網路」方印）不在本次範圍；它屬於圖形印記，辨識與否不影響 SC-004。
