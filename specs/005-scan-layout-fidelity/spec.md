# Feature Specification: 掃描 PDF 輸出的版面還原、勾選框與傾斜文字辨識

**Feature Branch**: `005-scan-layout-fidelity`

**Created**: 2026-10-16

**Status**: Draft

**Input**: User description: "優化掃描 PDF 辨識後的輸出：1) 輸出結構盡可能與原稿相同：保留表格線條（含框線、底線、虛線框）與表格／儲存格底色，以及文字顏色；2) 辨識勾選框（☐／☑），在輸出與預覽中保留勾選狀態，第二頁的申請表有很多；3) 提升傾斜中文字的辨識率（整頁傾斜、局部傾斜的手寫或名片），並處理整頁旋轉 90°／180° 的掃描檔；新增傾斜角度的評分樣本與結構（線條、底色、勾選框）的評分指標。"

延伸 `specs/004-scanned-pdf-ocr`。004 的輸出只有「辨識出的文字＋不含文字的圖片」，表格線、底色、勾選框都會消失，版面與原稿差距大；本規格補上這些結構，並提升傾斜文字的辨識。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 輸出的表格看起來和原稿一樣 (Priority: P1)

使用者去識別化一份掃描的名冊或發票，下載後的 PDF 仍有原本的表格框線、表頭底色與文字顏色，交給外部單位時版面一眼就能對照原稿，不會變成一堆漂浮的文字。

**Why this priority**: 表格與表單是掃描檔中個資最集中的版式；沒有框線，欄位對應關係就看不出來，輸出幾乎無法使用。

**Independent Test**: 對掃描範例去識別化並下載，比對輸出與原稿：表格的橫線、直線、表頭底色出現在相同位置；藍色手寫字、橘色公司名維持顏色。

**Acceptance Scenarios**:

1. **Given** 一頁含格線表格的掃描檔，**When** 去識別化並下載，**Then** 輸出在原位置畫出表格的水平與垂直線，粗細與顏色接近原稿。
2. **Given** 只有橫線的名冊、底線、虛線框，**When** 下載，**Then** 這些線條同樣保留（虛線框以虛線呈現）。
3. **Given** 表頭或儲存格有灰色或彩色底色，**When** 下載，**Then** 輸出在相同範圍填上相近的顏色，文字仍可閱讀。
4. **Given** 藍色手寫字或彩色印刷字，**When** 下載，**Then** 輸出的文字使用相近的顏色。
5. **Given** 預覽畫面，**When** 檢視掃描檔，**Then** 預覽同樣呈現線條、底色、文字顏色（預覽即輸出）。
6. 線條、底色、文字顏色都是重新繪製的乾淨圖形，不複製任何原頁面影像，因此不會夾帶文字。

---

### User Story 2 - 勾選框被辨識出來 (Priority: P1)

申請表、問卷上的勾選框（☐／☑）在輸出中保留原位置與勾選狀態，不會變成「口」「[」「了」之類的錯字。

**Why this priority**: 勾選狀態是表單內容的一部分（例如「同戶籍地址」「新申辦」），目前會變成雜訊並遺失。

**Independent Test**: 掃描範例第 2 頁的每個勾選框在預覽與輸出中都出現，勾選與未勾選的狀態和原稿相同，文字中不再有方框誤讀出的雜字。

**Acceptance Scenarios**:

1. **Given** 掃描表單上的空白方框與打勾方框，**When** 辨識完成，**Then** 每個方框以相同大小畫在原位置，打勾的方框畫出勾號。
2. **Given** 方框旁的選項文字（例如「新申辦」），**When** 檢視辨識文字，**Then** 選項文字保留，方框本身不再被讀成「口」「[」「了」「阿」等字。
3. **Given** 方框內是打叉或塗滿，**When** 辨識，**Then** 視為已勾選。

---

### User Story 3 - 傾斜或轉向的掃描也能讀對 (Priority: P2)

使用者用手機拍照或掃描時紙張放歪（數度傾斜），或整頁轉了 90°、180°；局部也可能有傾斜的手寫字或歪放的名片。系統先把頁面轉正再辨識，讀出的中文不因角度而大量出錯，輸出的頁面也是正的。

**Why this priority**: 使用者回報傾斜的中文字失敗率偏高；拍照與手動掃描很常見。

**Independent Test**: 同一份信函與表單以 0°、3°、6° 傾斜及 90°、180° 轉向產生測試樣本，辨識後的字元召回率與 0° 版本相近。

**Acceptance Scenarios**:

1. **Given** 整頁傾斜 3°–10° 的掃描，**When** 辨識，**Then** 系統偵測傾斜並轉正後辨識，輸出頁面是正的。
2. **Given** 整頁轉了 90°、180° 或 270°，**When** 辨識，**Then** 系統判斷方向、轉正後辨識。
3. **Given** 頁面只有不到 1° 的輕微傾斜，**When** 辨識，**Then** 文字照原樣辨識（避免重新取樣讓辨識變差），線條、底色與勾選框仍完整找出。
4. **Given** 辨識畫面，**When** 系統正在判斷方向或轉正，**Then** 階段文字說明正在進行的步驟。

---

### User Story 4 - 用原稿評分結構與角度 (Priority: P3)

開發者調整演算法時，評分工具除了文字與個資，也能回報線條、底色、勾選框的還原程度，以及不同角度樣本的辨識率，避免改善一處卻讓另一處退步。

**Independent Test**: 執行評分後，報表列出各頁線條召回／精確、底色命中、勾選框位置與狀態正確數，以及各角度樣本的字元召回率。

**Acceptance Scenarios**:

1. **Given** 掃描範例的原稿，**When** 評分，**Then** 原稿含有每頁的線條、底色與勾選框（含狀態），由產生範例的同一份來源匯出。
2. **Given** 角度樣本，**When** 評分，**Then** 分別列出 0°、3°、6°、90°、180° 的字元召回率。

### Edge Cases

- **細淡或斷續的框線**（影印不清）：盡量接成完整線段；無法判定的就不畫，不畫出不存在的線。
- **文字底線與刪除線**：視為線條保留；不得把文字筆畫（例如「一」）誤當成線條抹除或重畫。
- **照片中的直線**（機房照片的機櫃邊緣）：屬於保留的圖片，不另外畫線。
- **整頁有底色或紙張泛黃**：不畫成整頁底色；只保留明顯的表格／區塊底色。
- **方框形狀的字**（「口」「回」）：只有線條粗細、大小、四周留白都像方框時才視為勾選框；正文中的「口」不受影響。
- **嚴重傾斜（> 10°）或彎曲的紙面**：盡力轉正，不保證辨識率。
- **局部傾斜的手寫或歪放的名片**（整頁大致是正的）：沿用 004 的低信心第二意見重讀；以小角度旋轉重讀經量測沒有明顯改善（research R7），不納入。
- **方框與選項字被讀成同一個字**（☑男 讀成「Ms」）：選項字重讀後保留，方框以圖形重繪。
- **整頁轉向判斷不確定**：維持原方向，不亂轉。
- **還原頁**：還原只還原文字（沿用 004），不包含線條、底色與勾選框。
- **文字型 PDF**：不受影響，仍沿用原本的文字版面重建。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 偵測掃描頁上的水平與垂直線段（表格框線、底線、分隔線、虛線），並在輸出與預覽的原位置以相近粗細與顏色重繪；虛線 MUST 以虛線呈現。
- **FR-002**: 系統 MUST 偵測表格或區塊中明顯的底色（與紙色差異明顯的矩形區域），並在輸出與預覽的原位置以相近顏色填色，繪製在文字之下。
- **FR-003**: 輸出與預覽中的文字 MUST 使用接近原稿的顏色（黑、灰、藍、紅、彩色印刷等）。
- **FR-004**: 線條、底色、勾選框、文字顏色 MUST 以重新繪製的純色圖形呈現，不得複製原頁面影像的任何像素。
- **FR-005**: 系統 MUST 偵測勾選框（方形外框，大小約為一般文字高度），判斷是否已勾選（打勾、打叉或塗滿），並在輸出與預覽中以方框＋勾號的圖形重繪。
- **FR-006**: 被判定為勾選框的區域內，辨識產生的雜字（如「口」「[」「了」）MUST 從文字中移除；方框旁的選項文字 MUST 保留。
- **FR-007**: 系統 MUST 在辨識前偵測整頁傾斜角度（至少 ±10°）。傾斜 1° 以上時將頁面轉正後辨識，輸出與預覽的頁面為轉正後的方向；不到 1° 的輕微傾斜照原樣辨識與輸出，但線條、底色、勾選框仍 MUST 正確擷取。
- **FR-008**: 系統 MUST 判斷整頁方向（0°、90°、180°、270°），將轉向的頁面轉正後辨識；無法確定時維持原方向。
- **FR-009**:（評估後移除）原訂「低信心的局部文字以數個小角度重讀」。量測顯示沒有明顯改善、卻增加約 10%–18% 的辨識時間（research R7），因此不實作；傾斜文字由 FR-007、FR-008 處理。
- **FR-010**: 辨識畫面的階段文字 MUST 反映判斷方向、轉正、辨識、分析版面等步驟。
- **FR-011**: 掃描範例的原稿 MUST 增列每頁的線條、底色與勾選框（含勾選狀態）；另提供角度樣本（信函與表單在 0°、3°、6°、90°、180°）及其原稿，僅供評分使用、不放上網站範例區。
- **FR-012**: 評分工具 MUST 回報：線條召回／精確、底色命中、勾選框位置與狀態正確數、各角度樣本的字元召回率，並沿用既有的文字、個資與圖片指標。
- **FR-013**: 還原頁、文字型 PDF 與其他格式的行為 MUST 不變；004 的所有既有能力（偵測、取消、手動新增、保留圖片、輸出方式）MUST 維持。

### Key Entities

- **線段（Rule）**：所在頁、起點與終點、粗細、顏色、是否為虛線。
- **底色區塊（Fill）**：所在頁、矩形範圍、顏色。
- **勾選框（Checkbox）**：所在頁、位置、邊長、是否勾選。
- **文字顏色**：每段辨識文字附帶的顏色。
- **頁面方向與傾斜**：辨識前判定的整頁轉向（0／90／180／270）與傾斜角度。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 掃描範例中原稿列出的表格線段，輸出保留 90% 以上（位置誤差在 3pt 內），多畫出的線段不超過 10%。
- **SC-002**: 原稿列出的底色區塊，輸出命中 90% 以上，顏色與原稿相近。
- **SC-003**: 掃描範例第 2 頁的勾選框 100% 被辨識且勾選狀態正確；正文中沒有被誤判為勾選框的字。
- **SC-004**: 3° 與 6° 傾斜樣本的字元召回率與 0° 版本相差不超過 3 個百分點；90° 與 180° 樣本達 0° 版本的 95% 以上。
- **SC-005**: 掃描範例的字元召回與印刷值命中率不低於 004 的基準（98.8%、138/144），5 頁的總辨識時間增加不超過 30%。
- **SC-006**: 既有自動化測試全部通過；輸出 PDF 除了使用者保留的圖片外，不含任何點陣影像。

## Assumptions

- 只處理水平與垂直的直線與矩形底色；斜線、曲線、圓形、漸層等圖形不還原（以照片形式出現者沿用 004 的圖片保留）。
- 文字顏色以每段文字一個代表色呈現，不處理同一段內多色。
- 勾選框以方框＋勾號的標準圖形重繪，不保留原本的筆跡形狀；不輸出成文字字元（內建中文字型沒有對應字形）。
- 轉正後的輸出頁面為正向；頁面尺寸沿用原頁面（90°／270° 時寬高對調）。
- 傾斜偵測與方向判斷完全在瀏覽器內完成，不新增需要下載的模型。
- 角度樣本只存在測試資料中，用於評分與回歸檢查。
